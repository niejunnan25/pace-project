01 · Film

See the rule work, then see it everywhere.

One predicted chunk taken apart step by step (the rollout behind Figure 3 of the paper), then real ALOHA robots and simulated tasks.

50 actions predicted

An action-chunking policy proposes the next 50 joint commands. How many should the robot actually run before it looks again?

H chosen per chunk

PACE reads the speed of the predicted motion and stops at its first prominent slow-down, where one motion phase hands over to the next.

0 extra training

No model internals, no extra samples, no retraining. One threshold per task, calibrated from the demonstrations the policy was trained on.

02 · The rule

Execute until the motion settles. Then look again.

Below is the real rollout from Figure 3: place_shoe, episode 21. Every curve is computed from the policy's logged 50 × 14 action chunks with the released selector, and reproduces the logged horizons 32, 14, 37, 25, 19, 17.

  1. Predict a chunkThe policy outputs 50 future joint commands for both arms, as usual.
  2. Measure its speedPer arm, the speed between consecutive commands, smoothed with a Savitzky–Golay filter (window 11, order 3).
  3. Find the first real valleyA valley counts only if the speed first rose clearly above where the chunk started and then fell into it: contrast ≥ δ.
  4. Execute, discard, observeRun the prefix up to the earliest accepted valley of either arm, drop the rest, and query the policy on a fresh observation. No valley: run all 50.

05 · Other policies

Same rule, different policy, different actions.

GR00T N1.7 on all four LIBERO suites (40 tasks, 6,000 episodes per strategy). GR00T predicts 16-step Cartesian-delta chunks, so PACE reads the translational-delta norm instead of joint speed. Nothing is retrained.

Mean ± sample SD over three seeds; bold marks the best mean per column. Selector time 0.0566 ± 0.0046 ms per query; PACE uses 10.53 queries per successful episode vs 9.69 for full-chunk H = 16.

06 · Use it

Five lines between inference and execution.

The standalone module needs only NumPy and SciPy. Calibrated thresholds for all 50 RoboTwin tasks and the π0.5 evaluation code are released.
